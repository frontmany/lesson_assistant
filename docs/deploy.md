# Развёртывание

## Показ без сервера

Для показа хватает своего компьютера. Скрипт поднимает быстрые туннели Cloudflare к приложению и к LiveKit, записывает адрес LiveKit в файл настроек и перезапускает приложение. Бот открывает стартовую страницу, а она ведёт на адрес из `config.js` в репозитории `sferum-ai`. Скрипт печатает строку для этого файла. С флагом `--update-config` он сам записывает её туда, а после остановки возвращает прежний адрес. Для этого нужен `gh` с правом записи в `sferum-ai`. Без такого права адрес приложения указывают прямо в настройках бота как ссылку приложения. Скрипт следит за туннелями и поднимает их заново, а после остановки закрывает их и возвращает прежние настройки.

```bash
./scripts/tunnel.sh --update-config
powershell -ExecutionPolicy Bypass -File scripts\tunnel.ps1 -UpdateConfig
```

В файле настроек должны быть адрес компьютера в локальной сети и токен бота.

```bash
LIVEKIT_NODE_IP=192.168.1.10
MAX_BOT_TOKEN=токен бота
```

У такого показа три ограничения. Звук звонка идёт напрямую на адрес компьютера, поэтому телефоны должны быть в той же локальной сети. Туннель работает, пока включён компьютер и запущен скрипт. После перезапуска скрипта адрес меняется, и его снова записывают в `config.js` или в настройки бота.

## Сервер

Для постоянной работы нужна виртуальная машина с публичным адресом, двумя ядрами и четырьмя гигабайтами памяти. Обычный хостинг не подойдёт, звонку нужен UDP. Каждое демо запускает свой записанный класс из семи голосов. При меньшей памяти сервер уходит в подкачку, и звук в звонке прерывается.

Открыть нужно порты 80 и 443 по TCP для HTTPS, порты 7881 по TCP и 7882 по UDP для звука и порт 3478 по UDP для TURN. Без TURN звук может не пройти в закрытых сетях.

Файлы для сервера лежат в папке `deploy`. Там Compose с приложением, LiveKit и Caddy, настройки LiveKit и `Caddyfile`. Caddy сам получает сертификаты HTTPS. Если своего домена нет, подойдут имена `sslip.io`, они строятся из адреса машины. Данные приложение хранит в SQLite на диске сервера.

Образ приложения быстрее собрать на своём компьютере и перенести на сервер, чем собирать на слабой машине.

```bash
docker compose build app
docker save lesson_assistant-app:latest | gzip | ssh user@server 'gunzip | docker load'
```

Рядом с файлами из `deploy` на сервер кладут файл настроек. Ключ LiveKit, его секрет и подпись сессий задают длинными случайными строками.

```bash
APP_DOMAIN=203-0-113-10.sslip.io
LIVEKIT_DOMAIN=livekit.203-0-113-10.sslip.io
LIVEKIT_PUBLIC_URL=wss://livekit.203-0-113-10.sslip.io
LIVEKIT_API_KEY=ключ
LIVEKIT_API_SECRET=секрет
SESSION_SECRET=подпись сессий
MAX_BOT_TOKEN=токен бота
DEV_AUTH=0
```

Затем на сервере запускают стек.

```bash
docker compose up -d
```

С одним токеном бот работает только в одном месте, поэтому бота на своём компьютере перед этим останавливают. Адрес приложения записывают в `config.js` репозитория `sferum-ai` или указывают ссылкой приложения бота в MAX. После запуска звонок проверяют с двух телефонов в мобильной сети.
