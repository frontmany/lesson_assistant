# Развёртывание

Черновик: значения сверить с документацией LiveKit (docs.livekit.io, раздел про self-hosting).

## Что нужно

- Своя виртуальная машина с публичным IP: 2–4 ядра, 4–8 ГБ памяти. Обычный HTTPS-хостинг не подойдёт, звонку нужен UDP.
- Домен с двумя именами: `app.<домен>` для мини-приложения и `livekit.<домен>` для звонка.
- HTTPS для обоих: мини-приложение MAX открывается только по `https`, а со страницы по `https` браузер пускает в звонок только по `wss`.

## Порты

| Порт | Кому | Зачем |
|---|---|---|
| 443/tcp | всем | HTTPS приложения и `wss` LiveKit через обратный прокси |
| 7881/tcp | всем | медиа по TCP, если UDP закрыт |
| 7882/udp | всем | медиа по UDP |
| 3478/udp, 5349/tcp | всем | TURN для мобильных сетей и закрытых Wi-Fi |

## LiveKit на сервере

Режим `--dev` из `docker-compose.yml` на сервере не используем. Нужен свой конфиг, например `livekit.yaml`:

```yaml
port: 7880
rtc:
  tcp_port: 7881
  udp_port: 7882
  use_external_ip: true
keys:
  <LIVEKIT_API_KEY>: <LIVEKIT_API_SECRET>   # секрет длинный и случайный
turn:
  enabled: true
  domain: livekit.<домен>
  udp_port: 3478
  tls_port: 5349
```

Те же ключ и секрет — в `.env` приложения. `LIVEKIT_PUBLIC_URL=wss://livekit.<домен>`.

## Порядок

1. Поднять машину, открыть порты, получить сертификаты.
2. Запустить compose с боевым конфигом LiveKit.
3. Проверить звонок с двух телефонов в мобильной сети, без Wi-Fi.
4. Прописать адрес мини-приложения в настройках бота на business.max.ru/self и webhook бота.

## Показ без сервера

Пока своего сервера нет (#25), урок в MAX показывают с локального стека через временные туннели Cloudflare. Одна команда:

```bash
./scripts/tunnel.sh                                          # Linux
powershell -ExecutionPolicy Bypass -File scripts\tunnel.ps1  # Windows
```

С `--update-config` (в PowerShell `-UpdateConfig`) скрипт сам пушит адрес приложения в `config.js` репозитория `sferum-ai` — при запуске и после каждого обрыва, а после Ctrl+C возвращает адрес, который был там до запуска. Нужен `gh`, вошедший под аккаунтом с правом записи в `sferum-ai`. Это публикация: бот открывает `config.js` всем, кто нажал кнопку.

Что делает скрипт:

1. Поднимает стек (`docker compose up -d`) и два быстрых туннеля Cloudflare: на приложение (`localhost:8000`) и на LiveKit (`localhost:7880`). `cloudflared` берётся из системы, а если его нет — из Docker-образа `cloudflare/cloudflared`.
2. Пишет в `.env` `LIVEKIT_PUBLIC_URL=wss://…` и `DEV_AUTH=0`: через туннель урок открывают из MAX, и вход идёт по данным запуска, без `?id=`. Перезапускает `app`.
3. Печатает адрес приложения и строку для `config.js` в репозитории `sferum-ai`: бот открывает `frontmany.github.io/sferum-ai`, а тот ведёт на этот адрес. С `--update-config` пушит её сам.
4. Следит за туннелями: если `cloudflared` пишет «Tunnel not found», процесс умер или три проверки подряд сервис не отвечает через туннель, поднимает туннель заново и снова обновляет адреса. Новый адрес приложения снова нужно вписать в `config.js` — скрипт об этом пишет, а с `--update-config` пушит сам.
5. По Ctrl+C закрывает туннели, возвращает прежние `LIVEKIT_PUBLIC_URL` и `DEV_AUTH` и перезапускает `app`.

Нужно в `.env`: `LIVEKIT_NODE_IP` (адрес машины в Wi-Fi) и `MAX_BOT_TOKEN` (токен бота): без токена сервер не проверит данные запуска MAX и ответит «Не удалось проверить данные MAX». Скрипт без них не запускается.

Ограничения:

- **Звук — только в той же Wi-Fi-сети.** Через туннель идут страница и сигнализация звонка, а сам звук LiveKit шлёт напрямую на `LIVEKIT_NODE_IP` из `.env`. Телефон в мобильной сети войдёт в урок, но не услышит и не будет услышан: нужен TURN на сервере (#25).
- **Работает, пока включён компьютер** и запущен скрипт.
- **Адреса временные.** Быстрый туннель Cloudflare после перезапуска получает новый адрес, поэтому каждый раз обновляйте `config.js`.
- **Смена адреса LiveKit перезапускает `app`.** Идущий урок обрывается, и в него заходят заново.
- Если `config.js` оставить с мёртвым адресом, бот откроет нерабочую ссылку: после показа верните прежний адрес.
