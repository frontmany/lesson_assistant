# Развёртывание

## Показ без сервера

Для показа хватает своего компьютера. Скрипт поднимает быстрые туннели Cloudflare к приложению и к LiveKit, записывает адрес LiveKit в файл настроек и перезапускает приложение. Бот открывает стартовую страницу, а она ведёт на адрес из `config.js` в репозитории `sferum-ai`. Скрипт печатает строку для этого файла. С флагом `--update-config` он сам записывает её туда, а после остановки ставит `check.html`. Для этого нужен `gh` с правом записи в `sferum-ai`. Скрипт следит за туннелями и поднимает их заново, а после остановки закрывает их и возвращает прежние настройки.

```bash
./scripts/tunnel.sh --update-config
powershell -ExecutionPolicy Bypass -File scripts\tunnel.ps1 -UpdateConfig
```

В файле настроек должны быть адрес компьютера в локальной сети и токен бота.

```bash
LIVEKIT_NODE_IP=192.168.1.10
MAX_BOT_TOKEN=токен бота
```

У такого показа три ограничения. Звук звонка идёт напрямую на адрес компьютера, поэтому телефоны должны быть в той же локальной сети. Туннель работает, пока включён компьютер и запущен скрипт. После перезапуска скрипта адрес меняется, и `config.js` обновляют снова.

## Сервер

Для постоянной работы нужна виртуальная машина с публичным адресом, от двух до четырёх ядер и от четырёх гигабайт памяти. Обычный хостинг не подойдёт, звонку нужен UDP. Нужен домен с двумя именами, для приложения и для LiveKit, и HTTPS для обоих.

Открыть нужно порт 443 по TCP для HTTPS и защищённого WebSocket, порты 7881 по TCP и 7882 по UDP для звука, а также 3478 по UDP и 5349 по TCP для TURN. Без TURN звук не пройдёт в мобильной сети и в закрытых сетях.

Режим разработки LiveKit из `docker-compose.yml` на сервере не используется. Нужен свой конфиг с длинным случайным ключом и включённым TURN.

```yaml
port: 7880
rtc:
  tcp_port: 7881
  udp_port: 7882
  use_external_ip: true
keys:
  LIVEKIT_API_KEY: LIVEKIT_API_SECRET
turn:
  enabled: true
  domain: livekit.example.ru
  udp_port: 3478
  tls_port: 5349
```

Те же ключ и секрет пишутся в файл настроек приложения, а адрес LiveKit для браузеров указывается через защищённый WebSocket.

```bash
LIVEKIT_API_KEY=ключ
LIVEKIT_API_SECRET=секрет
LIVEKIT_PUBLIC_URL=wss://livekit.example.ru
DEV_AUTH=0
```

После запуска звонок проверяют с двух телефонов в мобильной сети, а адрес приложения указывают ссылкой приложения бота в MAX.
