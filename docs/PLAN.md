# Ассистент Сферум AI — план второго этапа

Команда «Пиксель»: Фёдор (капитан, мини-приложение и бот), Варвара (дизайнер), Ярослав (разработчик), Илья (аналитик).

Цель этапа — рабочий продукт: настоящий урок-звонок в MAX, в котором ассистент слышит каждого ученика и подсказывает учителю.

---

## 0. Что сдаём

Боту «Идея фикс» отправляем:

- ссылку на GitHub-репозиторий, в котором есть `Dockerfile`, `requirements.txt` и `README.md` с командами сборки, запуска и примером запуска из командной строки;
- ссылку на проект в MAX: бот и мини-приложение.

Что важно знать про MAX (dev.max.ru):

- **Мини-приложение** — веб-страница. Работает только по `https`, открывается только из бота: кнопка запуска настраивается на business.max.ru/self, прямая ссылка — `https://max.ru/<имя_бота>?startapp`. JS-мост — `window.WebApp`, данные запуска — в `window.WebApp.initData`.
- **Бот**: API `https://platform-api2.max.ru/`, токен в заголовке `Authorization`. Для разработки — long polling (`GET /updates`), для боевого режима — webhook по HTTPS (`POST /subscriptions`).
- Официального SDK для Python нет, ходим в API через `httpx`.
- **Работает ли WebRTC (звонок и микрофон) во встроенном браузере MAX, в документации не сказано.** Это первая проверка этапа.

## 1. Как работает продукт

1. Учитель пишет боту. Бот узнаёт его по аккаунту MAX и даёт кнопку «Начать урок», она открывает мини-приложение.
2. Мини-приложение заходит в **звонок урока**: одна комната LiveKit на урок. Ученики заходят из бота так же, каждый под своим аккаунтом.
3. Все слышат друг друга, как в обычном звонке. Горит индикатор «Аналитика активна».
4. **Ассистент** — скрытый участник той же комнаты. Он получает звук **каждого участника отдельным потоком**, поэтому точно знает, кто говорит, без распознавания по голосу.
5. Речь распознаётся, реплики размечаются, шкалы на экранах учителя и учеников растут по ходу урока.
6. Учитель нажимает «Завершить урок». Через 30–45 секунд бот присылает учителю сводку «кого о чём спросить», а ученикам — личные карточки.

## 2. Архитектура

```
 Учитель и ученики (мини-приложение)                 Сервер ассистента
┌──────────────────────────────┐   звук    ┌────────────┐  звук каждого   ┌────────────────────────────────┐
│ webapp: звонок + панель/шкала │◀────────▶│  LiveKit   │────участника───▶│ скрытый участник → VAD → ASR → │
│                               │  WebRTC  │   (SFU)    │                 │ тип реплики → шкала            │
│                               │◀─────────────────── события шкалы (WebSocket) ─────────────┘               │
└──────────────────────────────┘                                          └──────────────┬─────────────────┘
                                                                                         │ после урока
                                                              бот MAX ◀── сводка LLM ◀───┘
```

Решения:

- **SFU — LiveKit**, один Docker-контейнер. У него есть JS SDK для браузера и Python SDK, в котором сервер заходит в комнату скрытым участником и получает звук каждого человека кадрами 16 кГц по 30 мс. Janus из Callifornia не берём: с ним пришлось бы писать браузерный клиент и разбор RTP самим.
- **Сначала только звук.** Видео добавляем, если останется время: для ассистента оно не нужно.
- **Сервер приложения** — один процесс на FastAPI: API, токены входа в звонок, WebSocket событий, раздача мини-приложения, бот.
- **Python 3.12**: под 3.14 у faster-whisper (ctranslate2) может не быть готовых сборок.
- **Распознавание**: faster-whisper `base` в int8 на CPU (замеры в `analytics/README.md`); `small` — если останется запас по времени.
- **LLM для сводки** через переменные окружения, без ключа — шаблонная сводка.
- **Неопознанный участник не засчитывается никому.** identity в звонке = id ученика из состава класса.
- **Аудио на диск не пишется**, храним только реплики.
- **Виртуальный класс** — инструмент разработки, а не режим продукта: записанные дорожки заходят в звонок ботами. Так Ярослав отлаживает конвейер без людей, а Илья считает цифры качества на размеченной записи.

## 6. Порядок работ

Расписано на 14 дней. Если срок другой, этапы растягиваются или сжимаются пропорционально.

| Этап | Дни | Что делаем | Контрольная точка |
|---|---|---|---|
| 0. Звонок | 1–2 | `docker compose up`, две вкладки слышат друг друга; проверка звонка во встроенном браузере MAX; токен бота; сценарий урока | Два человека говорят друг с другом через наше мини-приложение |
| 1. Ассистент слышит | 3–5 | Скрытый участник получает звук каждого; VAD и распознавание; запись урока | Говорю в звонке — реплика с моим именем приходит в панель |
| 2. Функции | 6–9 | Все участники, тип реплики, шкала и норма, экраны по макетам, сводка и рассылка ботом, виртуальный класс | Урок от «Начать» до сводки в боте проходит целиком |
| 3. Качество и сервер | 10–11 | 6+ участников одновременно, задержка, замеры, развёртывание на сервер с UDP и TURN | Звонок работает с телефонов в мобильной сети |
| 4. Упаковка | 12–14 | Сборка с нуля, README, два полных прогона, сдача | Работа отправлена за сутки до дедлайна |

Критический путь: **звонок работает в MAX (дни 1–2) → ассистент слышит участников (день 5) → сервер с UDP и TURN (день 11).**

## 7. Процесс

- **Доска** в GitHub Projects: «Бэклог → В работе → На проверке → Готово». Одна задача — один issue.
- **Ветки**: `feature/<имя>-<что>`, в `main` только через PR. Все PR проверяет и одобряет Фёдор.
- **Созвоны** по 15 минут 3 раза в неделю. Остальное — в чате.
- **Пятничный прогон**: настоящий урок в звонке по `docs/scenario.md`, вся команда с телефонов.
- **Задача готова**, когда она в `main` и работает в `docker compose up`.
- Илья может писать код с ИИ-ассистентом: через PR и ревью он попадает в проект безопасно.

## 8. Риски

| Риск | Что делаем |
|---|---|
| Во встроенном браузере MAX не работает WebRTC или микрофон | Звонок открываем по ссылке из бота в обычном браузере, остальное без изменений |
| Хостинг не пропускает UDP | Своя виртуальная машина. LiveKit умеет медиа по TCP (7881) и TURN по TLS, но с большей задержкой |
| Телефоны в мобильной сети не соединяются | TURN-сервер LiveKit, см. `docs/deploy.md` |
| Распознавание на CPU не успевает за несколькими потоками | Модель `base`, распознаём только отрезки речи, ограничиваем число учеников на сервер |
| Эхо и чужие голоса в микрофоне | Шумо- и эхоподавление браузера включены по умолчанию. На проверках говорим в гарнитурах из разных комнат |
| LLM недоступна | Шаблонная сводка по результатам скоринга |
| Детская речь распознаётся плохо | Начинаем с 10–11 классов, меряем и не прячем цифры |
| Один разработчик — узкое место | Фёдор берёт мини-приложение, бота и сервер, Илья — скоринг. У Ярослава остаётся звонок → конвейер |

## 9. Что берём из Callifornia

- **Берём** идею медиабота (`CalliforniaDesktop/tools/mediabot`): синтетические участники звонка. У нас это виртуальный класс, который заходит в LiveKit ботами. Также подход к `docker-compose` и макеты из `CalliforniaDesktop/mock UI` как основу экрана звонка.
- **Не берём** Qt-клиент (в MAX не запустится) и Janus с Signaling и Auth: LiveKit закрывает то же самое быстрее.
