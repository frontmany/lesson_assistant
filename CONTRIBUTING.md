# Как мы работаем

## Задачи

- Все задачи — в GitHub Projects, колонки «Бэклог → В работе → На проверке → Готово».
- Одна задача — один issue: исполнитель, ожидаемый результат, срок. Шаблон — `.github/ISSUE_TEMPLATE/task.md`.
- Взял задачу — перенеси её в «В работе». Застрял больше чем на полдня — напиши в чат команды.

## Ветки и PR

- `main` всегда собирается и запускается.
- Ветка на задачу: `feature/<имя>-<что>`, например `feature/varvara-teacher-panel`.
- В `main` — только через pull request. Прямой push в `main` закрыт правилом репозитория. Шаблон PR подставится сам.
- Каждый PR проверяет и одобряет Фёдор (`.github/CODEOWNERS`), без его одобрения слить нельзя. Экраны и тексты интерфейса Варвара сверяет с макетами.
- `main` нельзя переписывать и удалять: GitHub отклонит и `--force`, и `--force-with-lease`.
- Свою ветку переписывать можно, но только через `git push --force-with-lease`: он не затрёт чужие коммиты, если в ветку кто-то успел запушить. Обычный `--force` не используем. Чужие ветки не переписываем и не удаляем.
- Писать код с ИИ-ассистентом можно и нужно. Главное — понимать, что делает код, и проверить его перед PR.
- Макеты в репозиторий попадают экспортом в `design/screens/`, чтобы код и дизайн можно было сравнить.

## Коммиты

Коротко и по-русски, в повелительном наклонении: «Добавь шкалу ученика», «Исправь задержку в WebSocket».

## Когда задача готова

- изменения в `main`;
- работает в `docker compose up`;
- если поменялся запуск или формат событий — обновлены README или `docs/contracts.md`.

## Ритм

- Созвон 15 минут три раза в неделю: что сделал, что дальше, где застрял.
- Каждую пятницу — настоящий урок в звонке по [docs/scenario.md](docs/scenario.md), вся команда с телефонов, даже если половина на моках.

## Контракты

Форматы событий описаны в [docs/contracts.md](docs/contracts.md) и в коде, в `app/models.py`. Если меняешь формат — меняй всё в одном PR: модель, моки в `webapp/mock/` и документ. Тест `tests/test_contracts.py` проверяет, что моки соответствуют моделям.
